## 2024-03-24 - Testing Beyer Projections
**Learning:** `calculateProjectedBeyer` is a pure function that relies on external data modules (e.g., `expectedBeyer`, `calculateClassBonus`, `getCourseForRace`). By isolating its tests and using Vitest module mocks, we can deterministically test the projection blending math (model expectations vs recent history) and distance bonuses without dragging in the complex simulation setup of the underlying dependencies. The recent history blending logic has a subtle edge case: it slices the first 3 recent races *before* filtering out races without Beyer figures, which is important to test to ensure the blend doesn't mistakenly fail when recent form has missing data.
**Action:** Always prefer mocking side-effect/heavy dependency imports (like `expectedBeyer` or track generators) when testing pure calculation logic to ensure the test solely covers the unit's responsibility (blending and distance bonuses) and runs quickly.
