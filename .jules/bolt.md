## 2025-03-01 - Optimizing buildFieldContext Array Allocations
**Learning:** Functions called within high-frequency loops (like `Track.tsx` per-frame renders, or even when hoisted but containing their own internal O(N) array passes) can be major sources of garbage collection overhead if they rely on chaining array methods (`.filter()`, `.reduce()`, `.map()`) or spread syntax (`[...arr]`). In `buildFieldContext`, chaining these methods caused multiple temporary arrays to be allocated and discarded.
**Action:** When optimizing functions running on the hot path, replace chained higher-order array methods and array spreads with a single standard `for` loop that aggregates all required state simultaneously into pre-allocated or local variables. For deterministic sorting, arrays can be sorted in-place before mapping them to rank dictionaries, completely avoiding intermediate array creation.
