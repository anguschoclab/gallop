## 2025-03-01 - Deduplicate ImpactHandlerFunction signature in resolver handlers
**Learning:** Found that multiple parallel modules in `src/core/resolver/handlers/` each defined an identical local `ImpactHandlerFunction` type signature for mapping impact types to handler logic. This is exactly the kind of duplication pattern that leads to inconsistency if the generic signature ever needs to change. `HorseHandler` was the exception with a slightly different signature involving an explicitly passed `horse` draft.
**Action:** Centralized the standard `ImpactHandlerFunction` definition into `src/core/resolver/handlers/types.ts` and exported it, then imported it across all handler modules that used the standard version, removing the local duplicate copies. For `HorseHandler`, renamed the local type to `HorseImpactHandlerFunction` to clarify its divergence from the centralized standard type.
