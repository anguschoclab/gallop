00 / Foundation

Vision & Pillars

Gallop is a single-player horse racing stable management sim — the depth of Football Manager's numerical engine with the visceral payoff of a live broadcast race.

What Gallop is

Authentic data, accessible UI. Real Beyer numbers, real pedigree dosage, real graded ladder — surfaced in scannable cards, sortable tables, and clear charts. Never in spreadsheets the player has to reverse-engineer.

Decisions over inputs. The player makes interesting choices (which race to enter, how to train this week, when to retire to stud), not tedious ones. UI removes friction and surfaces the trade-off.

Race day as the climax. Management screens feed the live race. The race is where training, breeding, and strategy pay off — visually, audibly, emotionally. The whole product flows toward that moment.

01
Authentic data, accessible UI
Real terms. Real metrics. Tooltips carry newcomers; veterans aren't slowed down.
02
Decisions over inputs
Every screen eliminates a friction point. The interesting choice stays; the tedious one disappears.
03
Race day as the climax
Management builds to the race. The race validates the management. Everything flows to that moment.

What Gallop is not

Not thisWhy it matters
A betting simPlayers manage outcomes, not wager on them. No RTP, no payout tables.
ArcadeNo power-ups, boost meters, or twitch input. Depth comes from data.
CartoonAuthentic terminology, authentic colours, authentic stakes. Not chibi, not kawaii.
GatedReal terms appear freely — the tooltip and glossary carry newcomers, never a paywall.
01 / Foundation

Personas

Every screen must serve at least two of these three archetypes. When in doubt, test against all three.

📊
Maya
The Numbers Trainer

Wants to optimise stats, Beyer trends, training programmes. Will read every number on every card. Can't stand ambiguity — if a figure is estimated, say so.

🌳
Tomás
The Romantic Breeder

Wants pedigrees, blue-hen mares, multi-generation lineage. Cares about dosage profile, sire lines, and the poetry of a well-matched cross. Numbers matter only when they tell a story.

🏇
Alex
The Tourist

Wants the thrill of race day without studying a manual. Enters the game through the front door — dashboard, "what do I do next?" — and follows the prompts. Never patronise Alex.

02 / Foundation

Design Principles

When two reasonable designs are on the table, these break the tie. They are deliberately opinionated. Walk them in order — the first that surfaces a problem is usually the right one to fix.

01
Numbers are the protagonist

Stats, times, prize money, and Beyer figures get the strongest visual treatment on a card. tabular-nums on every numeric column. Right-align. Bold the headline figure.

✓Bold Beyer, step everything else back
✕Glow effects or emoji competing with digits
02
Authenticity, not gatekeeping

Use the real word. Then make sure no one is left behind. Write G1 Stakes, Beyer 102, 3yo Maiden. Wrap racing jargon in a Tooltip the first time per screen.

✓"in foal to Justify" with tooltip on hover
✕"horse is pregnant by another horse"
03
The race day thread

Silk colours, surface textures, and broadcast palette thread through management screens. Race day is not a separate product — it's the same tokens, the same vocabulary.

✓Silk dot beside every horse name, everywhere
✕Two different silks on dashboard vs race screen
04
Density without claustrophobia

Stable management is a dense domain. Embrace it — but breathe. Use 8 / 12 / 16 / 24px gaps consistently. Pair a dense table with a roomy header.

✓Dense table + open section header = balance
✕Three different densities on a single screen
05
One verb per screen

Every screen has a primary verb: Train, Breed, Enter, Bid, Watch. One variant="default" Button visible above the fold. Everything else is secondary or ghost.

✓Single prominent "Enter Race" CTA in header
✕Five equally-weighted buttons vying for attention
06
State is visible, not implied

Loading? Show Skeleton. Empty? Write flavour copy. In progress? Show the timeline. The player should never wonder if the game is paused, broken, or waiting.

✓PregnancyTimeline showing every trimester marker
✕Blank table, "No data", hidden spinner
07
The race screen is the constitution

When management UI and race UI disagree, the race UI wins. Tokens, terms, silks, surfaces — all flow from race day. Management screens owe it consistency.

✓Grade colours on race screen = grade colours everywhere
✕Convenient hex codes that drift from broadcast tokens

07 / Design System

Motion

Animation has one job: tell the user something happened. It is never decoration. We use tw-animate-css for the standard library. No Framer Motion, no GSAP without a decision-log entry.

What we never animate

ElementWhy
NumbersBeyer figures and cash balances appear instantly. Counting-up animations feel toy-like and obscure precision.
Card hover liftCards use hover:bg-accent (colour change only). Transform on hover competes with scannable data.
Route transitionsRoutes swap instantly. We're a sim, not a marketing site.
Page-level animationsNo parallax, no entrance sequences on management screens. Race day gets the ceremony; management is immediate.

On the race screen: horses animate via pulse 0.5s ease-in-out infinite (CSS keyframes). Position updates each physics tick (50ms) via inline left%. prefers-reduced-motion is respected globally — all transitions collapse to 0.01ms.

Gallop is dense by design. The scannable stats row is the most important density pattern — left = identity, right = numbers, middle = qualifiers. The eye should identify a row in 0.3s, categorise in 0.6s, compare in 1.2s.

12 / Voice

Voice & Tone

Gallop's voice is knowledgeable, clear, quietly affectionate, never patronising. A knowledgeable trainer at the rail — happy to explain Beyer to a newcomer, but not slowing down to translate every term into baby-talk.

01
Knowledgeable

Use real terminology. G3 Stakes · 1600m · Turf · Firm — not "Tier-3 Big Race, 1 mile, on grass, dry surface."

02
Clear

Short sentences. Active voice. No hedging. "Beyer 102 — projected. Final figure available after the race."

03
Quietly affectionate

We like horses. We like players. We don't shout it. "Welcome back. Eight horses, one race today."

04
Never patronising

Never explain the same thing twice on the same screen. Never apologise. "You can't enter — the gelding restriction excludes him."

Tone matrix

ContextToneExample
Dashboard / idleComposed, factual"Two races today. Three horses ready to train."
TrainingCoach-like"Speed +2. Stamina holding. Energy down to 64%."
Race entryDeliberate, focused"Midnight Storm drawn 4 of 10. Post time: Tuesday."
Race result (win)Celebratory, precise"Midnight Storm wins the G1 Classic. Beyer 112 — career best."
Race result (loss)Frank, unsentimental"Finished 4th. Beyer 96. Seemed to tire in the final furlong."
Error / blocked actionDirect, non-apologetic"Can't enter — race is restricted to fillies."
Empty stateCalm, inviting"No horses in training. Head to the Stable to assign a programme."

15 / History

Decision Log

Append-only record of design decisions worth remembering. Each answers "why does it work this way?" so no one has to remember. Newest at bottom.

0001 · 2026-05-03
Active
OKLCH for all colour tokens

All primitive colour values use oklch(L C H). Perceptually uniform — equal L deltas feel like equal lightness. Makes light/dark pairs easier to balance. Consequence: hex, rgb, hsl banned in src/styles.css and components.

0002 · 2026-05-03
Active
Sidebar nav is flat, 7 items

Dashboard, Stable, Races, Rival Stables, Market, Breeding, Sales. Adding an 8th item requires a vision-level conversation. Sub-paths reachable from inside parent screens — not in nav.

0003 · 2026-05-03
Active
Race screen breaks AppShell

AppShell early-returns <Outlet /> for any path starting with /race/. The race is full-bleed. Consequence: race screen must implement its own back-out navigation.

0004 · 2026-05-03
Active (planning)
Broadcast theme planned, not yet implemented

Race screen uses inline emerald values — deliberate gap, not drift. Fix as a single coordinated change introducing .broadcast class with full token coverage. Don't fix piecemeal.

0005 · 2026-05-03
Active
No emoji in body copy (weather excepted)

One exception: weather indicator on race screen (☀️ Sunny, 🌧️ Wet). Keeps voice composed. Emoji as decoration would complicate future i18n.

0006 · 2026-05-03
Active
Silks are the only approved inline style colour

Silk colour is per-horse user data — not theme. style={{ backgroundColor: horse.silkColor }} is approved everywhere a silk dot appears. Always pair with a token-driven border.

0007 · 2026-05-03
Active
Charts capped at 5 series

Use chart-1–chart-5 only. If you need 6, the chart is doing too much — split it. For 8-horse race-pace charts, use highlight + grey-out or small multiples.

0008 · 2026-05-06
Active
Grade colours use app theme tokens

G1 = fame (gold), G2 = muted-foreground (silver/secondary), G3 = info (blue/tertiary). Single source of truth in src/core/race/grading.ts:getGradeColorClass(). All duplicate implementations deleted from route files.

16 / Extension

How to Extend

The design system is stable enough to build on and open enough to grow. These checklists prevent drift.

Adding a new colour token

/* 1. Add primitive value in :root and .dark */ :root { --surface-broadcast: oklch(0.45 0.12 155); } .dark { --surface-broadcast: oklch(0.40 0.10 155); } /* 2. Register as semantic token in @theme inline */ @theme inline { --color-broadcast-track: var(--surface-broadcast); } /* 3. Consume in component as Tailwind utility */ <div className="bg-broadcast-track">

Adding a new domain component

StepWhat to do
1. Check personasWhich of Maya / Tomás / Alex does it serve? It must serve at least one clearly.
2. Check for existing componentCan an existing domain component be extended? Prefer extension over creation.
3. Apply principle 7If it appears on both management and race screens, the race-screen version wins for any shared visual decision.
4. Single primary actionThe component exposes one dominant CTA (principle 5). If it needs more, split the component.
5. Tabular numericsAny numeric column in the component uses tabular-nums. Non-negotiable.
6. Document hereAdd entry to the domain components table above. Add entry to decision log if a non-obvious choice was made.

Adding a new screen

Every screen follows the template in docs/design-bible/05-screens/00-screen-template.md. Mandatory fields: primary persona, primary verb, empty state copy, loading state, URL/route, and which of the 7 principles the screen expresses most strongly.

Navigation: a new top-level route requires a sidebar entry and the 7-item flat-nav decision (0002) must be revisited. A sub-route inherits its parent's sidebar entry and uses breadcrumbs or a back-button within the parent's chrome.

Adding a new theme

All semantic token names must be declared in the new theme. You cannot partially apply a theme — every --background, --foreground, --card, etc. must have a value. New roles that only exist in the theme (e.g. --broadcast-track) must be registered in @theme inline and documented in 01-design-system/05-theming.md.
